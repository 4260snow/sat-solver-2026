Нужно реализовать свой SAT-решатель на основе алгоритма DPLL.

Реализацию следует начать с `raise NotImplementedError()` в файле [`solver.py`](solver.py).
Так как ваш код будет запускаться в отдельном потоке с ограничением по времени, не забывайте в реализации
регулярно проверять `self.sigkill.is_set()`, и, если он возвращает `True`, ваш код должен завершить работу
(через `return SATSolverResult.UNKNOWN`).

## Что уже есть в заготовке

Обязателен только интерфейс, который вызывает `solver_test.py`: `Solver(filename, sigkill).solve()`.
Всё остальное в [`solver.py`](solver.py) — заготовки, которыми можно пользоваться, менять или
выбросить: структуру решения, эвристики и структуры данных вы выбираете сами.

Предполагаемое разбиение — три метода с `raise NotImplementedError()`: `propagate()` (UnitPropagate),
`choose_literal()` (ChooseLiteral) и `solve()` (основной цикл DPLL).

- **Литералы — неотрицательные числа**: `x_v → 2v`, `¬x_v → 2v+1`. Отрицание — `l ^ 1`,
  переменная — `l >> 1`. Всё, что хранится «по литералу», — обычный `list` длины `2n+2`.
- **Формула**: `self.formula.clauses` — дизъюнкты из файла. Метод `preprocess()` разбирает их на `self.clauses` (длины ≥ 2, без повторов
  литералов и тавтологий `a ∨ ¬a`), `self.units` (литералы единичных дизъюнктов) и флаг
  `self.has_empty_clause`.
- **Откат состояния** вместо копирования множества дизъюнктов, как на слайде:
  `values[ℓ]` (`1` / `-1` / `0`), трейл `trail` с указателем `propagated`, стек уровней `control`
  и операции `assign`, `decide`, `decision`, `backtrack`.
- **Индексы для поиска дизъюнктов** — постройте тот, что подходит вашему решению:
  - `build_occurrences()` — списки вхождений литералов: для DPLL на счётчиках, чистых литералов,
    некоторых эвристик;
  - `build_watches()` — наблюдаемые литералы (`binary[ℓ]` для бинарных дизъюнктов, `watches[ℓ]`
    с литералами-блокерами для остальных).

### Подсказки

- Если пишете рекурсию, как на слайде, помните: в тестах есть формулы с более чем 1000 переменных,
  а глубина рекурсии в Python по умолчанию ограничена 1000 (и решатель работает в отдельном потоке
  с небольшим стеком). Проще написать поиск итеративно, со стеком решений.
- Помнить, какие ветки уже пробовались, можно без отдельного стека флагов: при конфликте на уровне `L`
  взять решение `ℓ = decision(L)`, откатиться на уровень `L - 1` и сделать `assign(¬ℓ)` как вывод на этом
  уровне. Конфликт на уровне 0 означает UNSAT.
- С наблюдаемыми литералами при просмотре `watches[ℓ]` (ℓ стал ложным) полезно: сначала проверить
  блокер; второй наблюдаемый литерал — это `c[0] ^ c[1] ^ ℓ`; если в дизъюнкте нашёлся истинный
  литерал — сделать его блокером, а не переносить наблюдение.

## Условия принятия

Ваш код будет запускаться на тестах в GitHub Actions после каждого push на GitHub.
Вы можете запустить тесты локально, вызвав `python solver_test.py`.
После исполнения будет напечатано примерно следующее:

```
Your solver RANK: 68.2178617730
Your score for this homework: 6 points
```

Первое число (`68.2...`) - **ранк** вашего SAT-решателя. Чем он меньше, тем лучше.
На основании него высчитывается второе число (`6 points`) - **ваша оценка за это задание**.

### Об оценивании

- Максимально возможное число баллов за решение - 10
- Оценка вычисляется в функции `test_dpll`: `min(10, round(10 · 70 / (ранк + 40)))`.
  Полный балл ставится при ранке не больше 30, дальше оценка плавно убывает.
- Для ориентира:

  | Решение | Ранк | Баллы |
  |---|---|---|
  | DPLL дословно по слайду (множества дизъюнктов копируются на каждом шаге) | 50–70 | 6–8 |
  | DPLL на счётчиках с эвристикой выбора литерала | 25–45 | 8–10 |
  | DPLL на наблюдаемых литералах | ~12 | 10 |

- Ранк складывается в основном из нерешённых тестов (по 10 за каждый), поэтому важнее решить как можно
  больше тестов за отведённое время, чем ускорять и без того быстрые

### Ограничения
- если в коде реализован не DPLL (или его вариации, например, с 2-watch-literals или CDCL), задание **не засчитывается**
- использовать сторонние библиотеки (например, `numpy`) запрещено
